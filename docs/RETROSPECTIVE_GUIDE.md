# Retrospective guide (500-800 words)

This one has to be **yours**. I can't write it for you: it's reviewed for being specific to *your* build, and "what specifically changed in how you work?" is the point. Write it to the person you were in Week 1. Save as `docs/RETROSPECTIVE.md`.

## Structure
1. **What I set out to do** (about 100 words): what did you think this track would be? What did you expect to build?
2. **What changed** (about 250 words): concrete moments, not feelings. Ideas from this project to react to, *only if true for you*:
   - the first version of the chatbot vs the eval that exposed its failures (v1 36/38; prompt injection got a menu dump)
   - the day your credits ran out and you needed an offline path: what did that teach you about depending on one service?
   - the moment you noticed the info sheet and the menu disagreed (the flourless almond cookie) and moved everything to one data file
   - what you now check before trusting an AI answer
3. **What I'd build next** (about 100 words)
4. **The three most transferable things I learned** (about 150 words): things that would help on a totally different project.

## Rules of thumb
- Name specific things: a file, a bug, a number, a decision.
- Include one thing that went wrong and what you did.
- Mention where AI helped and where you had to correct it (transparency).
- Count words: 500-800.

Tip from the course: once drafted, paste it into Claude with your README and ask it to mock-interview you about your own build and point out where the project is weakest. Then you can talk about that honestly.
